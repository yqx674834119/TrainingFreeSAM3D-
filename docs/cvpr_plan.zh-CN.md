# Granularity Alignment：方法与实验设计（CVPR 投稿规划 v2）

v2 相对 v1 的改动：放弃「training-free 的 ESAM」这一叙事，改成把**粒度**本身立成问题
与贡献。ESAM 从「要追赶的对象」变成「被我们解释的基线」。所有标 **[已测]** 的数字都有出处，
标 **[待做]** 的是设计意图。需要你拍板的点集中在 §8。

## 1. 一句话定位与标题

**一句话**：SAM/FastSAM 这类分割基础模型并没有答错问题，它回答的是**另一个粒度上的问题**；
3D 实例分割指标（IoU/AP）把这种「粒度不同」和「识别错误」记成了同一个数字。我们把
**粒度对齐（Granularity Alignment）**立成一个独立任务，证明它是 3D 实例分割误差的主导项，
并且**不需要任何训练**就能解——因为这个操作本质是在 query 图上做一次带稳定性判据的合并，
可迁移、可在线、可扩展到整场景。

标题候选：

1. *Segment Anything, at Any Granularity: Training-Free 3D Instance Alignment for Streaming Scenes*
2. *The Model Is Not Wrong: Granularity Alignment for Open-World 3D Scenes*
3. *From Parts to Places: A Training-Free Granularity Operator for Scalable 3D Scene Segmentation*

我推荐 1：它把「零训练」和「粒度可控」两个卖点都放进标题，而且不出现 ESAM。

**摘要草稿（中文，供你改写成英文）**

> 视觉基础模型的分割输出与 3D 数据集的实例标注处在不同的粒度上：前者给的是部件，
> 后者标的是物体。我们在 ScanNet 上量化了这一错配的代价——保持 FastSAM 的 mask 集合
> 完全不变、只允许改变分组方式，平均最佳 IoU 就从 0.532 升到 0.784，召回@0.5 从 0.515
> 升到 0.871；而一个训练了 128 个 epoch 的 4700 万参数 3D 解码器只到 0.754，甚至没有超过
> 「只合并相邻组」的 GT 上界 0.769。这说明 3D 实例分割的瓶颈不是「看不出来」，而是「分
> 不清尺度」。据此我们把粒度对齐形式化为独立任务：给定冻结的分割模型与目标粒度，输出
> 该粒度下的 3D 划分。我们提出一个不需要训练的对齐算子：把互斥 mask 提升为 query，
> 在外观—几何联合图上做带**稳定性判据**的合并——阈值由合并树的持续区间决定而非在训练集
> 上调参，因此换数据集、换粒度都不需重训。算子同时给出在线扩展：跨帧关联完全由冻结特征
> 的矩阵运算完成，场景记忆以 query 为单位、规模与帧数无关。在 ScanNet200 上……（待填）

## 2. 问题重述：把粒度立成任务

### 2.1 为什么原来的故事不行

「training-free 的 ESAM」是一个**减法**故事：去掉 3D U-Net、去掉训练、性能接近 ESAM。
它的天花板由 ESAM 定义，审稿人只需问「那和 ESAM 比差多少」就能压住。新故事必须是**加法**：
我们指出一个此前没有被量化的问题，给出一个新的任务定义、一个新的判据、一套新的评价，
并顺带解释为什么一个 4700 万参数的训练版方法其实大部分在做图操作。

### 2.2 任务定义

**Granularity Alignment (GA)**。给定：

- 一个冻结的 2D 分割基础模型 $S$（FastSAM / SAM / SAM2 / …），
- 一段 posed RGB-D 流，
- 一个**目标粒度** $g$：可以是某个数据集的标注约定、一个任务要求，或用户给的一个标量
  （目标实例数 / 目标尺度），

输出：该场景在粒度 $g$ 上的 3D 实例划分，且要求

- (R1) **零梯度训练**：不训练任何分割网络，也不为本数据集微调；
- (R2) **粒度可迁移**：换 $g$ 不重训、不重新标定阈值；
- (R3) **在线且内存有界**：流式处理，记忆规模与帧数无关；
- (R4) **与 $S$ 无关**：换基础模型不改方法。

这四条要求每一条都直接对应下面一个贡献，也各自对应一张实验表。

### 2.3 粒度的形式化

数据集标注 $G$ 与模型输出 $P$ 都是点集上的**划分**。IoU 只在「同一个点被判给同一个
实例」的意义上比较两者，因此它无法区分两种失败：

- **识别失败**：模型没见过这个物体，或边界不准 → 需要更好的模型；
- **粒度失败**：模型把物体的部件各自分开了，部件本身几乎完美 → 需要的是**重组**，不是训练。

我们用一个干净的方式拆开它们：**固定 mask 集合，只改变分组算子**。

| 层次 | 定义 | 含义 |
|---|---|---|
| Raw | 每个 FastSAM 互斥组直接当一个实例 | 粒度完全由 VFM 决定 |
| **Merge-only oracle** | 允许任意合并，purity ≥ θ | **任何只做合并的方法的上界** |
| Merge-adjacent oracle | 只允许 3D 相邻（<5 cm）的组对合并 | 我们这类算子的上界 |
| Split-boundary oracle | 允许逐点拆分 + 合并 | 加入边界修整后的总上界 |

三个数字的间距就是误差归因。1,388 个 thing GT（3D GT，≥100 点）上的 **[已测]**：

| 量 | 数值 | 说明 |
|---|---|---|
| FastSAM raw（最佳单组） | IoU 0.532 / 召回@0.5 0.515 | 部件粒度 |
| Merge-only oracle | **0.784 / 0.871** | 只重组的上界 |
| Merge-adjacent oracle | 0.769 / 0.847 | 只允许相邻对 |
| ESAM（训练版，47M） | 0.754 / 0.837 | 训练出来的结果 |
| ESAM-snap（只保留其整组合并部分） | 0.702 / 0.792 | 说明 ESAM 大部分在合并 |
| 每 GT 碎片数 | FastSAM 2.22 → oracle-adj 0.97 → ESAM 1.07 | 粒度对齐的直接读数 |

**论文的三句关键论断**（每一句都要有数）：

1. 掩码固定、只改分组，IoU 从 0.532 升到 0.784：**粒度错配是误差的主导项**，不是识别问题。
2. 只允许相邻组合并的上界（0.769）**已经超过**一个 47M 参数的训练版解码器（0.754）：
   **训练一个分割器不是解决这个问题的必要条件。**
3. ESAM 的每个 mask 平均由 7.0 个 FastSAM 组构成、82% 合并了 ≥2 组，且只保留其整组
   合并部分就拿到全部提升的 77%：**训练版方法做的也主要是这个算子**，我们把它显式化。

**新指标**（要定义得能被人引用）：

- **Granularity Gap (GG)** $= \mathrm{IoU}_{\text{oracle-merge}} - \mathrm{IoU}_{\text{raw}}$：
  一个模型在该数据集上「粒度不匹配」引起的可回收误差。
- **Fragments per GT**：每个 GT 被几个高纯度 mask 覆盖（我们已有实现）。
- **Granularity controllability curve**：把粒度设定沿谱扫一遍，画 IoU/AP，标出 GT 粒度所在
  的位置；曲线峰值是否落在 GT 粒度上、且**没有被告知** GT 粒度，是方法是否真的「对齐」的证据。

## 4. 方法

```
                    ┌──────────── 冻结，不训练 ────────────┐
RGB-D 流 ─► FastSAM ─► 互斥分组 ─► 逐点特征 Fp ─► query: q = (F_s, 几何描述子, 支撑集)
                                                        │
        ┌───────────────────────────────────────────────┴──────────────┐
        │                                                              │
   M2 帧内粒度算子                                               M3 跨帧关联
   联合图 → 边统计 → 合并树 → 稳定性判据选划分                 外观×几何 的矩阵匹配
        │                                                              │
        └──────────────────────────► M4 有界 query 记忆 ◄──────────────┘
                      生成 / 吸收 / 稀疏化 / 回收 / 拆分检查
                                      │
                              物体层级 ─► 房间/楼层层级（同一算子，换粒度）
```

### M1 Query Lifting：把表示换成 query **[已实现，已测]**

与 ESAM 逐条对齐，只把 3D U-Net + Memory Adapter 换成冻结特征采样。但**叙事要变**：
表示的单位不再是点，而是 **query**。这一步决定了后面全部复杂度都在 $O(G)$ 个 query
（每帧约 73 个）而非 $O(N)$ 个点上（20000），也决定了记忆可以按实例而不是按点来存。

要点（都是踩过的坑，写进论文的 implementation details）：

- 互斥分组沿用 ESAM：mask 按面积降序写入，小 mask 覆盖大 mask；未覆盖点 KMeans(20) 补组。
- 逐点特征 $F_p$：点像素中心在特征图上双线性采样（`padding_mode='border'`，否则边缘点与零混合）。
- **语义/身份用 `backbone`（stride 32，640 维），边界对比必须用 `proto`（stride 4，32 维）**。
  用 stride-32 计算 5 cm 内的交界对比时两点落在同一格，正负样本都是 0.99，零信号 **[已测]**。
- query 特征 $F_s$：组内平均池化 + L2，并**减去帧均值**。FastSAM 特征经 SiLU 后有巨大公共
  分量（`neck_p3` 的 mask 对 cosine 挤在 0.85–1.0，gap 0.01），减帧均值后 gap 0.23 → 0.41 **[已测]**。

### M2 帧内粒度算子：从阈值调参到稳定性判据

**图的构造**：节点 = query，边 = 3D 相邻组对（<5 cm）。实测每帧 ≈73 节点 / ≈410 边 /
平均度 11.3 **[已测]**。边特征 14 个标量（建图时顺带算出，模型只见标量）：

| 组 | 特征 | 最强项 |
|---|---|---|
| 外观 | `group_cos`、边界点对两侧 $F_p$ 的 cosine（proto） | `group_cos` 正 0.67 / 负 0.02 |
| 几何 | `min_dist`、边界长度（点对数/较小组点数）、深度差、`contact_norm`、法向夹角、高度差 | `min_dist`、法向 |
| 尺寸 | 点数比、包围盒 IoU、合并后凸性变化 | 中等 |
| **结构** | **原始 mask 嵌套**（互斥化之前一个 mask 是否被另一个包含） | 正 0.36 / 负 0.002，最便宜 |

**能量视角**（这是把方法讲「科学」而不是讲「启发式」的地方）。把划分 $P$ 的代价写成

```
E(P) = Σ_{簇内边} w(i,j)  −  λ · Σ_{跨簇边界} b(i,j)  −  μ · (#簇 的粒度先验)
```

`w` 是「同物体」的闭式得分（外观一致性 + 接触强度 + 嵌套），`b` 是边界代价（法向夹角、
深度跳变）。ESAM 训练出来的解码器可以看作这个能量的一个隐式 argmin；我们直接算它。
**平均连接聚类是它的贪心近似**——这解释了为什么单连接会链式过合并（0.570 vs 平均连接
0.627 **[已测]**），也告诉我们该在哪里加约束。

**关键新意（C2 的核心）**：$\lambda$ 的选定**不在训练集上调**。做法是对合并树做
**持久性/稳定性选择**：沿阈值谱扫描，一个簇的「寿命」（它作为独立簇存在的阈值区间长度）
超过判据才被接受——即 maximally stable clustering。这样：

- 不需要任何数据集的 GT 来标定阈值 → 满足 R2（换数据集不重训、不重标定）；
- 目标粒度 $g$ 可以作为**约束**注入（给定目标实例数、或区域内目标尺度），得到一个
  「粒度旋钮」，而不是重训；
- 现阶段我们是在 60 个留出训练场景上标定 τ 的 **[已测]**，稳定性判据是要替换掉它的东西，
  也是把方法从「调参」抬到「判据」的关键一步。

### M3 跨帧关联：把冻结特征当成身份信号 **[部分有雏形，待系统化]**

你已经观察到的现象值得单独做成一个研究点：**冻结的基础模型特征可以支撑跨帧 3D 匹配**。
论文里要把它讲成「外观与几何的互补性」而不是「我们又做了一次匹配」：

- 匹配得分 = 外观相似度 × 几何重叠（照 ESAM `OnlineMerge` 的乘性形式），全部是矩阵运算：
  `S = (Z_cur @ Z_next.T) * GeoOverlap`，几何项用轴对齐 bbox 的 3D IoU（ESAM-E 本身就用
  `AxisAlignedBboxOverlaps3D`）或体素质心距离，**无 KD-tree、无逐边 Python 循环**。
- 要给出的分析（这是新贡献）：
  - 把关联错误分成两类：**几何歧义**（两个物体贴着，几何分不开）与**外观歧义**（同类
    物体彼此相似）。前者靠 $F_s$ 解决，后者靠几何/时序解决，做成一张 2×2 的分解表。
  - 用 **ID-switch rate** 与关联 F1 作为独立于 AP 的评价轴（流式场景下 AP 会掩盖身份抖动）。
- 诚实说明损失：ESAM 的匹配里有 `sem_preds`（分类头输出）这一项，我们没有分类头。
  必须消融证明「外观 + 几何」足够，或用一个无需训练的替代（例如 query 的语义伪标签，
  OpenMask3D 风格，或者用 CLIP 在 query 上打一个开放词汇标签）。

### M4 有界 query 记忆：为什么我们现在能 Scale Up

这是 C4，也是你提的「大场景 Memory」问题。要点是**记忆的单位从点变成实例**。

**实例记录**（每条固定大小）：

| 字段 | 内容 | 大小 |
|---|---|---|
| `z` | 外观原型，$F_s$ 的 EMA 池化 + L2 | d × 4 B（如 256 维 = 1 KB） |
| `support` | 几何支撑：体素哈希 key 集合（2–5 cm 体素），**上限 S 个**（空间分层抽样保留） | S × 8 B（S=256 ⇒ 2 KB） |
| `bbox` | 轴对齐 bbox（匹配剪枝用） | 24 B |
| `counters` | 点数、吸收次数、首/末次见到、稳定性分 | ~32 B |

**管理操作**（全部不需要学习）：

1. **生成**：匹配得分低于阈值则新建实例；
2. **吸收**：匹配则 EMA 更新 `z`、支撑集体素并集（只处理新增体素，$O(\text{new voxels})$）；
3. **稀疏化**：支撑集超过 S 就按空间分层抽样抽稀，保证**上界**；
4. **回收 / 唤醒**：连续 N 帧未见且支撑很小的实例降级到「休眠池」（只保留 `z` 与 bbox），
   后续靠外观匹配唤醒，避免长流中实例数无界增长；
5. **拆分检查**：一个实例的支撑集若在空间上呈双峰（PCA 双峰性 + 连接处细颈检验），
   标记为需要拆分候选——这正好对上我们目前 22% 的 GT 落在「不纯组、需要拆分」这一桶。

**内存量级（可解析计算，写进论文）**：

| 方案 | 表示 | T=1000 帧时的量级 |
|---|---|---|
| ESAM 式稠密 | `(K, T·N)` bool mask，K=200, N=20000 | ≈ 4.0×10⁹ B ≈ **3.7 GiB**，随 T 线性增长 |
| ESAM 式附加 | `(K, T, 256)` query 特征 float32 | ≈ 2.0×10⁸ B ≈ **205 MB**，随 T 线性增长 |
| **本文 query 记忆** | K × (1 KB + 2 KB + 56 B) | K=200 ⇒ ≈ **0.6 MB，与 T 无关** |

两个数量级以上的差距，而且我们的方案显存占用有硬上界。**另外要指出 ESAM 的关联代价**：
它每帧对全部实例做一次 $K\times K$ Hungarian（$O(K^3)$），在大场景里 K 会涨到数百上千；
我们先用空间哈希 + 外观近邻剪枝把候选降到局部，再对每个连通分量做批量分配，接近线性。

**层级扩展（把「大场景」做实）**：同一个算子在更粗的粒度设置下给出房间/楼层划分，
于是输出不止是实例，而是**层级化的 3D 场景结构**（物体 → 房间 → 楼层）。这和你在
`ditr_work` 里的 HOV-SG 房间层级工作天然衔接，也是「Scale Up」从「更多帧」升级为
「更大空间尺度」的地方。

## 5. 与已有工作的关系（避免活在阴影里）

| 方法 | 它做的事 | 我们与它的关系 |
|---|---|---|
| ESAM / ESAM-E | 训练 47M 3D 解码器，用 VFM 特征预测逐点 mask | **我们解释它**：它的收益 77% 来自整组合并，而只合并相邻组的上界（0.769）已超过它（0.754）。它是我们最好的基线，也是我们的论据 |
| SAM3D / SAMPro3D | 直接堆 VFM mask，离线，粒度不匹配 | 我们的 C1 正好量化了它们吃亏的地方 |
| SAI3D / SAMPro3D | 离线、几何合并；SAMPro3D 发布了更细的 ScanNet200-Fine50 标注 | 它们把粒度当数据设定；我们把**粒度当可调维度**，并用 Fine50 标注做粒度迁移实验（本地已有 40 个场景） |
| 2D 部的粒度/层次分割（如 SAM 的 part 模型、层次分割） | 在 2D 里做 part-whole | 我们把它搬到 3D 并在 3D 上给出在线、有界记忆的算子 |

一句话差异：**别人训练模型去适配粒度；我们把粒度变成算子的一个参数。**

## 6. 发散：还能做成贡献的点（按「新意 × 可行性」排序）

1. **粒度作为提示（granularity prompt）**：除了数据集粒度，还支持「给我 N 个实例」、
   「只在桌子高度以下按家具粒度分」这类交互式设定。零训练让它变成可行产品特性，
   而不只是论文里的一个数字。
2. **粒度可控性的定量评价**：controllability curve + 峰值是否落在 GT 粒度上（无需告知），
   做成一个可复用的评价协议。
3. **跨粒度一致性**：同一场景在物体粒度与 Fine50 粒度下的划分应当**嵌套**（细的是粗的
   细化）。把这个「层级一致性」当成约束/评价，是很强的新意（本地两套 GT 让它可做）。
4. **跨会话合并**：同一房间两次独立扫描，用 M3 的冻结特征匹配合并成一套实例——直接
   展示「不需要训练也能做场景级融合」。
5. **VFM 无关性**：FastSAM / SAM / SAM2.1（本机 `/home/yqx/VLN/assets/sam/` 有 SAM2.1
   hiera large 与 base_plus）跑同一套算子。图表很好看，而且证明这是关于粒度的性质，
   不是关于某个模型的技巧。
6. **把「全体边 AUC 是错的评价」写成方法论教训**：我们的探针显示特征只值 +0.01 AUC，
   但下游 IoU 涨了 0.041 **[已测]**。原因：决定聚类的是**难边**，全体边 AUC 掩盖了它们；
   且 AP50 的提升主要来自节点级 objectness（有特征 0.794 vs 纯几何 0.724 **[已测]**）。
   给出正确的诊断（按边难度分层的 AUC / 聚类目标的一致性），这本身就是可写的一小节。
7. **开放词汇下游**：把粒度可控的 mask 喂给 OpenMask3D。可以展示「粒度选择影响开放词汇
   分类精度」——这是给「粒度可控」找到真实用途的最短路径。
8. **失败学的定量刻画**：目前 15% 已经很好的 GT 被过度合并 >0.1 IoU，查了 172 例 **[已测]**：
   114 例是**不同类别**的相邻物体（背包放在脚凳上）、31 例同类别、27 例并入墙/地面。
   这是一张很好看的失败饼图，也直接论证了为什么节点需要外观特征。

## 8. 风险与预案

| 风险 | 影响 | 预案 |
|---|---|---|
| 「零训练」被质疑（我们现在最好的结果来自 40k 参数的边分类头） | C2 站不住 | 三档并报：**A 手设阈值（零拟合）**、**B 闭式线性（15 个标量，推荐主结果）**、C 40k 头（上界变体）。主表用 A/B，C 只出现在消融里 |
| 稳定性判据不如调参阈值 | C2 的核心新意失效 | 先做小规模对照（协议 A），若持平就把主张收敛成「无需 GT 的判据」，并保留调参版本作为上界 |
| 22% 的 GT 落在不纯组、需要拆分 | 与 ESAM 的差距解释不掉 | 明确写 limitation；stretch goal 是**无训练**的边界修整（用 proto 特征做贪心切分） |
| 312 场景数据与 ESAM 的 stride 不一致 | 主表不可比 | 见 §9.2，必须在两周内定路线 |
| 流式实验工程量大 | C4 缩水 | 先用解析内存曲线 + 1000 帧长流做最小验证，HM3D 多房间放到最后 |
| 「就是阈值 + 合并」 | 审稿人觉得 trivial | 靠 C1 的量化诊断、稳定性判据、粒度迁移与扩展性四点支撑；能量视角也写进去 |

# 跨帧合并 v2：用同一个 MergeNet 合并"本帧"和"历史"

给人看的版本。要交给 AI 执行的步骤、文件和验收标准见
[stream_merge_v2_plan.zh-CN.md](stream_merge_v2_plan.zh-CN.md)。

**一句话**：帧内合并和跨帧合并是同一件事：判断两块东西是不是同一个物体，是就粘起来。
第一帧没有历史，就是现在的 MergeNet；之后每一帧，把"历史物体"和"本帧碎片"一起交给同一个
MergeNet 来粘。历史可能粘错，所以**最近几帧（默认 5 帧）粘过的东西允许重新粘**，更早的定稿。

---

## 1. 我们已经知道什么

逐帧（16 个验证场景、809 帧，thing 实例，平均最佳 IoU，出处 `esam_granularity`、`merge_net`、
`mask_scorer` 三份文档）：

| 方法 | 平均最佳 IoU | 说明 |
|---|---|---|
| FastSAM 原始碎片 | 0.532 | 每个物体平均被切成 2.2 块 |
| GroupMergeNet | 0.627 | 我们训练的合并模型 |
| 提议打分 | 0.688 | 目前逐帧最好 |
| ESAM 只做合并的部分 | 0.702 | |
| ESAM 完整版 | 0.754 | |
| Oracle（GT 告诉你哪些相邻碎片该粘） | 0.769 | 只靠合并的上限 |

三点结论：

1. ESAM 的提升大部分来自"把碎片粘起来"。
2. **只靠合并就有可能超过 ESAM**（0.769 > 0.754）。这是 GT 指导的上限，
   我们的模型目前还没做到（0.627 / 0.688）。
3. 剩下的差距一部分是"粘得不够准"，一部分是"一块碎片里混了两个物体"（约 22% 的物体），
   后者只靠合并修不了。

跨帧（场景级，16 个场景，ESAM 网格，段平滑后的 AP50，出处 `streaming` 文档）：

| 方法 | AP50 |
|---|---|
| 现在的记忆，纯几何 | 0.272 |
| 现在的记忆 + 投影特征（当前默认） | 0.365 |
| 同一个记忆，输入换成"GT 提议"（来源待确认，见 §9） | 0.513 |
| ESAM-E | 0.589 |

## 2. 现在的跨帧合并为什么不好

1. **每次只看一帧就下结论。** 新的一帧来了，只拿它和历史的"平均样子"比一次，配上就配上，配不上就新开一个。
2. **只合不拆，错了就永远错。** 仓库里能看到两种错：同一个物体开了好几页（早先检查 75 页里有 26 页重复）；
   两个挨着的物体被并成一页（scene0488，AP50 0.150，ESAM 0.875）。
3. **每帧的分割互不相关。** 这一帧给"整把椅子"，下一帧可能只给"椅背"，记忆要靠一套规则去猜它们的关系。

---

## 3. 新的任务定义

- **碎片**：某一帧 FastSAM 切出来的互斥小块（就是现在 MergeNet 的输入）。
- **历史**：一份物体清单。每个物体由两部分组成：
  - **定稿部分**：超过 5 帧以前粘进来的东西，已经压成一团，不再改；
  - **可改部分**：最近 5 帧里粘进来的碎片，还记得"这是第几帧的哪几块"。

**T0（第一帧）**：没有历史。MergeNet 把这一帧的碎片粘成物体，得到第一版历史。

**T1 及以后**：手里有历史，又来了一帧新碎片。还是同一个 MergeNet，把下面这些东西放在一起重新判断谁和谁该粘：

- 本帧的新碎片；
- 最近 5 帧粘过的东西；
- 历史物体的定稿部分（只取和这些东西挨着的）。

粘完以后：

- **本帧的物体** = 每一组里属于本帧的那些碎片，这就是逐帧结果；
- **新的历史** = 每一组就是一个物体；最老的那一帧滑出 5 帧窗口后，压进对应物体的定稿部分。

T0 就是"历史为空"的特殊情况，所以两个阶段是同一个任务、同一个网络。

---

## 4. 每一帧具体做什么（拼图版）

1. **摆出来**：本帧的碎片、最近 5 帧粘过的块、挨着的定稿物体，全部摆在桌上。
2. **两两打分**：MergeNet 给每一对挨着的东西打一个"是同一物体"的分数。
   不挨着的不打分（它们不可能是同一个物体），这样要算的对数很少。
3. **分组**：按分数把东西分成若干组。规则是"两组之间所有配对的平均分够高才合并"，
   一条错误的高分边不会把两个物体连起来（现在的 MergeNet 就是这么做的，仓库里验证过比"连通就合并"好：0.627 对 0.570）。
4. **记下来**：
   - 一组里有定稿物体 → 这一组就是那个物体；有两个定稿物体 → 说明它们是同一个，合并成一个；
   - 一组里没有定稿物体 → 沿用这些块上一帧的物体编号；全是新碎片 → 新开一个物体（太小的不开）。
5. **滑窗口**：最老的一帧离开窗口，它的块压进对应物体的定稿部分。

---

## 5. 怎么改错，改得了什么

**改得了：**

- 最近 5 帧里某一块被粘错了物体 → 新证据来了之后，它可以被重新分到别的物体；
- 同一个物体开了两页 → 两个定稿物体之间也打分，分数高就合并。

**改不了（第一版）：**

- 超过 5 帧的定稿部分：为了速度，不再改；
- 同一帧里一块"内部"混了两个物体：第一版里，过去帧的单位是"这一帧粘成的一整块"，只能整块换物体，不能拆开。
  第二版把过去帧的单位换成原始碎片，就能拆，但要多算很多对（作为消融实验做）。

**为什么只改最近几帧**：能改的东西越多，桌上摆的东西越多，每帧越慢。5 帧是起点，会测 1/3/5 帧的效果和速度。

---

## 6. MergeNet 要改的三处

**① 多认识两种东西：过去帧的块、定稿物体。**
现在 MergeNet 只见过同一帧的碎片。这些碎片互不重叠，只是挨着，所以它的输入全在描述"两块怎么挨着"。
跨帧的两块不一样：同一个物体从两个角度看两次，空间上会**大面积重叠**。所以要加的最重要的输入是：

| 新输入 | 人话 |
|---|---|
| 重叠多少 | 两块在 5 cm 小方块上有多少是共用的 |
| 谁包含谁 | 一块是不是几乎整个落在另一块里（部件 vs 整体） |
| 隔了几帧 | 同一帧、隔 2 帧、还是很久以前 |
| 是什么东西 | 本帧碎片 / 过去帧的块 / 定稿物体 |

原来那 14 个"怎么挨着"的输入照用，只是只有本帧碎片之间才有，其它配对填 0。
大小、高度、形状、颜色、外观特征这些对所有东西都能算，照用。

**② 历史要记住"由哪些碎片粘成"。**
这是能改错的前提。只存一团粘好的点，发现错了也拆不开；存了"第 3 帧的 A 块、第 5 帧的 B 块"，就能重新判断。
只对最近 5 帧这么存，更早的压成一团，所以历史不会无限变大（也不再是严格固定大小，这一点你已经同意）。

**③ 输出多两样东西。**
除了"两块是不是同一物体"，再让网络判断：

- 这个东西**是不是一个物体**（不是墙、地面）——用来给最后的物体排序，算 AP 要用；
- 这个东西**是不是混了两个物体**——用来防止它继续吸别的东西，以后也用来决定拆分。

---

## 7. 为什么仍然快

和 ESAM 一样：每帧只算一张"谁和谁该粘"的打分表，再按表分组，全是矩阵运算，没有逐点循环。
区别只是表里的东西多了：ESAM 是"新 mask × 历史"，我们是"(本帧碎片 + 最近 5 帧的块 + 挨着的物体) 之间两两"。

粗算（未实测）：本帧约 70 块碎片，过去 4 帧每帧约 12 块（MergeNet 现在每帧输出约 12 个 mask），
再加几十个挨着的物体，总共约 150 个东西，只给挨着的配对打分。网络打分现在是 2 ms 级别；
分组要换成"只看有边的配对"的写法（现在的写法是稠密矩阵，东西一多会变慢）。目标是记忆这一步每帧 20 ms 以内，实测后写进结果。

## 8. 实验计划：三步，每步回答一个问题

**第 0 步：用 GT 测上限（不训练）。**
把 MergeNet 的打分换成 GT（该粘的一定粘），按上面的流程在线跑。同时用同样的输入跑两个对照：

- ESAM 的跨帧合并规则（特征相似度 × 包围盒重叠，一对一配对，我们按它的代码重写）；
- 现在仓库里的记忆。

再加一个"直接按 GT 编号归类"的天花板。
**怎么判断**：如果"我们的流程 + GT"明显高于"ESAM 规则 + 同样的 GT 输入"，说明框架方向对，值得训练；
如果不高，先改框架，不训练。这一步做完会停下来给你看结果。

**第 1 步：训练统一的 MergeNet。**
需要先在训练场景上做一份"连续帧"的缓存（现在训练缓存每个场景的帧隔得太远，没法学跨帧）。
训练分两轮：先用 GT 粘出来的历史来学；再让模型自己跑，用它自己犯错后的历史再学一遍（这样训练和使用时看到的历史一致）。
**检查**：关掉历史、只跑单帧，结果应该接近现在 MergeNet 的 0.627，否则说明有 bug。

**第 2 步：在线评估和改错消融。**
在 16 个验证场景上和现在的 0.365、ESAM-E 的 0.589 比。
再比：窗口 1 帧（不改错）/ 3 帧 / 5 帧；过去帧用"整块"还是"原始碎片"；关掉"物体之间合并"。
同时统计重复页和错误合并有没有变少，以及每帧耗时。

## 9. 结果（第 0 阶段 + 第 0b 阶段）

**第 0 阶段（GT oracle 在线跑）**：窗口记忆用 GT 打分（该粘的一定粘），16 个验证场景、809 帧。
窗口 1 / 3 / 5 帧的段平滑后 AP50 逐位相同（0.362）——在 GT 等价关系下"粘错"不会发生，所以"改错窗口"没有价值。
这个数与现有默认流程（0.365）几乎一样，但覆盖率明显更高：平均最佳 IoU 0.768（默认 0.458）、召回@0.5 0.877（默认 0.498）、
mask 112 个/场景（默认 36 个）。ESAM-E 是 0.589。

**第 0b 阶段（输出端上限，不训练）**：在"合并完美"之上补输出端处理，回答"AP 到底卡在哪"。

- **修正第 0 阶段的说法**：合并决定覆盖率（IoU 0.458 → 0.768），AP 卡在输出端的清理和排序。
- **垃圾 mask 从哪来**：段平滑后 112 个 mask 里 75 个是垃圾（最佳 IoU < 0.25）；其中 90% 只被看到 1 帧、
  88% 由不纯碎片组成、72% 不到 500 顶点、墙/地/天花板占 0%。本质是"单个视角里的不纯碎片自己开了一个物体"。
- **AP 的真正上限**：完美合并 + 完美排序 + 场景级 NMS = **0.877**（段平滑后），明显高于 ESAM 的 0.589；
  比"ESAM 的输出 + 完美排序"（0.724）还高 0.153——我们的 mask 底子本身就更好。
- **不用 GT 能做到多少**：**0.721**（现有分数排序 + NMS + 丢掉只出现一帧的物体）。离上限 0.156，差距主要在排序：
  同样清理下换完美排序 +0.092；同样排序下换"用 GT 挑不纯"只 +0.003（清理已基本做满）。
- **两个免费信号很值钱**：只把排序换成"观测帧数"（记忆本来就统计）不清理：0.362 → 0.647；
  只加"NMS + 丢只出现一帧"不换排序：0.362 → 0.721。第 2 阶段的打分器要补的就是剩下那 0.092 的排序差距。
- **体素渲染天花板**：网格 GT 走 5 cm 体素再渲染回网格几乎无损（AP50 1.000）；同机制换成真实观测点（逐帧 20k 点、全帧累计）也有 0.965。
  旧文档 0.788 的"体素上限"复现不出，以本次重测为准（细节见 `work_dirs/stream_v2/phase0b/summary.md`）。

去向分解、4×4×2 组合与参考行的完整表格在 `work_dirs/stream_v2/phase0b/summary.md`；执行记录见计划文档「第 0b 阶段」。

## 10. 风险和还没确定的事

**风险**

- **逐帧最好的路线会丢一部分。** 目前逐帧最好的是"从 FastSAM 原始 mask 里挑"（0.688），新框架回到"粘碎片"（0.627 起步）。
  会把"有一个高质量原始 mask 同时盖住这两块"作为打分的输入，尽量把这部分收益找回来，但能找回多少要实测。
- **错误会滚雪球。** 一块被粘错，这个物体之后可能吸更多错的东西。窗口改错和"是否混了两个物体"的判断用来缓解。
- **同一块里混两个物体（约 22%）第一版仍然修不了。**

**需要确认**

1. 文档里"GT 提议喂同一记忆 0.513"是怎么跑出来的？现在的 `tools/stream_eval.py` 只有
   `--scorer oracle`（FastSAM 提议 + 真实 IoU 打分），不是真正的 GT mask。第 0 步会重新测真正的 GT 版本。
2. 训练要新建连续帧缓存，估计几 GB、按之前的速度三张卡约半小时到一小时，需要你在机器上跑。
3. 主指标用场景级 AP50（段平滑后），逐帧 IoU 作为辅助，是否同意？
